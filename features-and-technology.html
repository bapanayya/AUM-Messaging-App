1. Executive Overview & Architectural Paradigm

Modern digital communication has long been dominated by centralized client-server silos that harvest user interaction graphs, log private contacts, and retain encrypted or unencrypted media indefinitely on central servers. AAM fundamentally re-architects this model.

Sovereign Device-First Model

Primary Device Storage

In AAM's default architecture, the sender's and recipient's hardware devices serve as the single source of truth. The application core stores zero persistent plaintext or media content in central databases. Content is held securely in the sender's client database until the recipient connects, establishing direct peer-to-peer delivery.
Pure Privacy Architecture

Zero Behavioral Harvesting

AAM eliminates all third-party tracking scripts, advertising auction SDKs, behavioral analytics, and telemetry beacons. User identity discovery is strictly mutual via verified contact requests, ensuring no spam, unsolicited scraping, or unsolicited message delivery.

2. Core Innovation: The 3 User-Selectable Storage Modes

AAM empowers each user to choose their preferred data residency model during onboarding, with instant, transparent migration available at any time through the in-app Storage Management center.

Mode 1 • Default & Free

Local Device Storage

Zero Cloud Footprint. All messages, high-resolution photos, audio recordings, and videos reside exclusively on the user's physical device.

  • Persistent Cloud Footprint: 0 Bytes (Zero)
  • Recipient Offline Flow: Sender-Side Queue
  • Signature Feature: "My Pending Transfers"
  • Delivery Model: Direct WebRTC / ephemeral relay
Mode 2 • Safety Tier

Local Store + Encrypted Backup

Hardware Loss Protection. Device remains primary working store, with on-demand or scheduled encrypted snapshot backups.

  • Key Management: Client-derived passphrases
  • Cloud Payload: Opaque ciphertext blob
  • Server Visibility: Cannot read or restore backups
  • Portability: Seamless restore on new device
Mode 3 • Multi-Device

Paid Encrypted Cloud Sync

Multi-Screen Real-Time Sync. Messages and media synchronize across phones, tablets, and desktops seamlessly.

  • Offline Delivery: Server holds ciphertext buffer
  • Sender Online Requirement: None
  • Encryption: E2EE envelope before network transmit
  • Cloud Storage: Zero plaintext retention

3. Comprehensive Feature Suite Breakdown

Every feature in AAM was engineered from first principles to balance modern user expectations with strict data sovereignty.

Core Communication

💬 End-to-End Encrypted Messaging (1:1 & Groups)

Full-fidelity private messaging supporting text, high-resolution photography, 1080p video, and voice notes.
  • Cryptographic Safety Numbers: 12-digit visual fingerprints (e.g. 4820 9183 2049) generated from SHA-256 digests of public keys to verify contact identities out-of-band.
  • 4-Tier Delivery Receipts:
    • 🕒 Pending (Clock): Recipient offline; queued locally on sender's device.
    • ✓ Sent (Single Check): Transmitted to network gateway.
    • ✓✓ Delivered (Double Check): Received by recipient device.
    • ✓✓ Read (Double Blue Check): Decrypted and viewed by recipient.
  • Interactive Audio Notes: Live Web Audio waveforms rendered dynamically with play/pause and progress scrubbing.
  • Social Expressiveness: 1-tap emoji reactions (👍, ❤️, 😂, 😮, 😢, 🙏, 🔥), message starring, and full search.
Real-Time Audio / Video

📞 WebRTC Peer-to-Peer Voice & Video Calling

Direct peer-to-peer real-time communication engine delivering ultra-low-latency calls with zero server audio/video interception.
  • 1-on-1 & Group Calling: Dynamic SDP offer/answer exchange and ICE candidate negotiation over WebSockets.
  • Procedural Web Audio Ringtones: Built-in dual-tone audio oscillator synthesizer producing realistic caller and ringback tones without downloading external MP3 files.
  • Complete In-Call Suite: Live call duration counter, microphone mute, camera toggle, and front/back lens flipping.
  • Sovereign Call History: Local-only call logs detailing incoming, outgoing, and missed calls with 1-tap redial.
Signature Innovation

⏳ "My Pending Transfers" Sender-Side Queue

The visible manifestation of AAM's Mode 1 architecture:
  • Transparent Queue Inspector: When a recipient is offline, outbound media and files are not stored on foreign cloud servers. They remain indexed locally in the sender's client database.
  • Granular Control: Senders view recipient name, file format, thumbnail, payload size (KB/MB), and timestamp.
  • Actionable Management: Provides instantaneous Manual Retry to trigger immediate peer reconnection or Cancel to purge queued transfers before delivery.
Social Discovery

🎬 Daily Moments Feed (Chronological Media Stream)

A vertical, frictionless daily timeline of photographs and video clips shared exclusively by accepted contacts.
  • 24-Hour Rollover: Content posted to Daily Moments stays highlighted for the current day.
  • Automatic Midnight Archiving: At 00:00, moments automatically fold seamlessly into regular private chat histories, preventing stale clutter.
  • Private Conversational Replies: 1-tap "Reply in Private Chat" initiates an immediate end-to-end encrypted message referencing the moment.
Ephemeral Social

⭕ 24-Hour Ephemeral Status Updates

Disappearing ephemeral storytelling with customizable text and photography.
  • Vibrant Gradient Text Stories: Instant status publishing with curated gradient palettes (Saffron Aura, Sovereign Bharat, Deep Space).
  • Photo Stories: High-definition image uploads with custom captions and duration tags.
  • Auto-Advancing Engine: Smooth 6-second segment progress bars with pause-on-hold interaction.
  • Viewer Insights: Real-time viewer counter showing exactly which mutual contacts opened the status.
Contact Commerce

📢 Sovereign Ads Space (Vertical Full-Screen Showcase)

A full-screen vertical swipeable showcase enabling users, creators, and local businesses to broadcast advertisements directly to their accepted contacts.
  • Immersive Vertical Layout: Auto-looping video and photo showcases with custom price badges and category chips (e.g. #Handloom, #Artisan, #Festive).

Sovereign Graph

4. Complete Technology Stack & Specifications

The application is architected across four distinct layers: modern single-page web client, native hybrid mobile shell, real-time backend signaling gateway, and automated CI/CD release engineering.

Frontend Architecture

React 19 & TypeScript Client

  • Core Framework: React 19.x with functional components and modern concurrency hooks (useState, useEffect, useContext, useRef).
  • Language: TypeScript 5.8 with strict typing across state models, API contracts, and WebSocket event payloads.
  • Build Engine: Vite 5.x delivering sub-second HMR, tree-shaking, and minified production bundles.
  • Styling & Design System: Tailwind CSS v4 with custom dark mode theme variables, glassmorphic filters, and touch-optimized responsive layout.
  • Vector Iconography: Lucide React for crisp, scalable UI icons.
  • Hardware Cryptography: Web Crypto API (window.crypto.subtle) for hardware-accelerated AES-GCM 256-bit encryption and SHA-256 hashing.
  • Web Audio Engine: Web Audio API (AudioContext) with procedural sine/square oscillators for zero-dependency ringtone generation and dynamic voice waveforms.
  • Peer-to-Peer Media: WebRTC APIs (RTCPeerConnection, navigator.mediaDevices.getUserMedia, ICE candidate negotiation).
Mobile Platform

Capacitor 6 & Android 15 (SDK 36)

  • Hybrid Bridge: Capacitor 6.x (@capacitor/core, @capacitor/android, @capacitor/cli) converting modern web applications into native Android binaries.
  • Target Android SDK: SDK 36 (Android 15), strictly complying with Google Play's latest target API requirements.
  • Compilation SDK: SDK 36 with Java 21 LTS build tooling.
  • Minimum Android SDK: SDK 24 (Android 7.0 Nougat), providing 96%+ global device coverage.
  • Cryptographic Release Signing: Production keystore (upload-keystore.jks) utilizing 2048-bit RSA keys and SHA-256 with RSA signatures.
  • Distribution Formats:
    • Android App Bundle (AAB): Optimized for Google Play Store dynamic split delivery.
    • Universal APK: Direct sideloading and internal hardware testing.
Backend & Gateway

Node.js, Express & WebSocket Gateway

  • Runtime: Node.js v20 / v22 LTS with ES module execution.
  • Server Framework: Express.js with TypeScript supporting REST endpoints for auth, profile, contacts, storage, and feed.
  • Real-Time Duplex Gateway: ws WebSocket server handling persistent presence heartbeats, instant message dispatch, delivery receipts, and WebRTC signaling (SDP offer/answer, ICE candidates).
  • Data Layer: Pure relational JSON database engine (server/src/db/storage.ts) with atomic buffer writes, maintaining zero plaintext chat data in Mode 1.
  • Authentication: Salted password hashing via bcryptjs, JSON Web Tokens (JWT), and secure UUIDv4 session identifiers.
DevOps & Cloud

GitHub Actions CI/CD Pipeline

  • Two-Stage Web Deployment: deploy.yml splitting compilation (build job on Node 22) from publication (deploy job with official actions/deploy-pages@v4) to eliminate artifact indexing race conditions.
  • Android Release Automation: android-build.yml orchestrating JDK 21 setup, Android SDK command-line tools installation, Gradle daemon execution, and automated signing of production AAB and APK packages.
  • Automated Releases: Automatic publishing of compiled release binaries to GitHub Releases on tag or workflow completion.
  • Static Hosting: Zero-cost, high-availability hosting on GitHub Pages with .nojekyll SPA routing.

5. Client-Side Sovereign Storage Engine

To allow the web application to run completely standalone on static hosting platforms (such as GitHub Pages) and mobile devices without requiring a locally running Node.js server, AAM incorporates an intelligent dual-mode storage engine.

Hybrid API Fallback Architecture

1

Primary Live API Probe

When the application launches, the API layer checks if a live backend server is accessible at /api or http://localhost:5000.

2

Graceful Client-Side Sovereign Fallback

If the network request encounters a timeout, connection refusal, or mixed-content block (as occurs when a GitHub Pages HTTPS site tries to fetch local HTTP), the client automatically activates client/src/services/mockStorage.ts.

3

Local Device Persistence

The sovereign client store initializes realistic Indian demo seed datasets into browser localStorage, persisting user messages, status updates, contact lists, and ads locally across page reloads.
